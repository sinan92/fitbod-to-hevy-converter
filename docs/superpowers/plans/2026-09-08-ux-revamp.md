# UX/UI Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved one-page design in `docs/superpowers/specs/2026-09-08-ux-revamp-design.md`: dark, centered, three-step rail as progress, receipt after conversion, English copy.

**Architecture:** `App` keeps one `phase` signal (`idle | reading | done | error`) plus `fileName`, `result`, `errorMessage`. Everything the template shows (rail states, headline, work area) is `computed()` from those. The converter gains `firstWorkout`/`lastWorkout`. Styles live in `app.scss` with CSS custom properties defined in `styles.scss`.

**Tech Stack:** Angular 22 standalone + signals, Vitest + TestBed, SCSS. Load the `frontend-design` skill before Task 3.

## Global Constraints

- Copy is exactly the text in the spec's "Copy (final, English)" section.
- No new dependencies, no external fonts, `color-scheme: dark`.
- Converter change limited to two additive fields on `ConversionResult`.
- No commit without user authorization (already given for this branch's work: commit per task).

### Task 2: Component state model and template (English copy)

**Files:**
- Modify: `src/app/app.ts`, `src/app/app.html`, `src/index.html`
- Test: `src/app/app.spec.ts`

**Interfaces (Produces):**

```ts
export type Phase = 'idle' | 'reading' | 'done' | 'error';
export type StepState = 'pending' | 'active' | 'done';
export interface Step { number: 1 | 2 | 3; title: string; hint: string; state: StepState; }
class App {
  readonly phase: Signal<Phase>;
  readonly fileName: Signal<string>;
  readonly result: Signal<ConversionResult | null>;
  readonly errorMessage: Signal<string>;
  readonly steps: Signal<Step[]>;            // derived
  readonly headline: Signal<string>;         // derived
  readonly lead: Signal<string>;             // derived
  readonly dateRange: Signal<string>;        // "2023-10 → 2025-09"
  readonly visibleUnmapped: Signal<string[]>; readonly hiddenUnmappedCount: Signal<number>;
  readonly showAllUnmapped: WritableSignal<boolean>;
  handleFiles(files: ArrayLike<File> | null): Promise<void>;
  reset(): void;           // → idle
  download(): void; saveFile(file: File): void;
  onDragOver/onDragLeave/onDrop/onFileInput
}
```

Rail derivation (`steps` computed):
- step 1: `done` when `fileName() !== ''`, else `pending` (never active: the user did it in Fitbod; hint tells them how).
- step 2: `done` when `phase() === 'done'`, else `active`.
- step 3: `active` when `phase() === 'done'`, else `pending`.
- Hints: 1 → `Fitbod → Log → ⋯ → Export Data`, or the file name once chosen; 2 → `Drop the file here` / `Converting…` / `N sets converted`; 3 → `Hevy → Profile → Settings → Import data` / `Now in Hevy`.

- [ ] Step 1: Rewrite `app.spec.ts` to cover: idle shows drop zone + step 2 active; success shows receipt numbers, 6 chips + `+ N more`, expands on click, next-step card, step 3 active, `saveFile` once, headline `Done. Check, then import.`; error shows `role=alert` with the converter message and `Try another file` returns to idle; two files → error; `Convert another file` returns to idle; date range text `2023-10 → 2023-10` for the fixture. Use `fixture.nativeElement.querySelector` and `await fixture.whenStable()` after each action.
- [ ] Step 2: Run tests → failures.
- [ ] Step 3: Implement `app.ts` (state + computed), `app.html` (structure per spec: brand, headline, lead, rail `<ol>`, work area `@switch (phase())`, next-step card, footer). Hidden text for rail state: `<span class="sr-only">Step {{n}} of 3, {{state}}</span>`. Drop zone = `<label>` wrapping the hidden input + a `<button type="button">` that calls `input.click()`; `tabindex="0"` + `(keydown.enter)`/`(keydown.space)` on the label. Body-level `dragover`/`drop` prevention via `@HostListener('document:dragover')`/`('document:drop')` calling `preventDefault()`.
- [ ] Step 4: `index.html` title `Fitbod to Hevy converter`, `<meta name="theme-color" content="#0b0d12">`.
