# SEO Implementation Plan — Fitbod to Hevy converter

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Someone who searches for "fitbod to hevy", "import fitbod into hevy" or "fitbod export csv hevy" finds https://sintaxcode.nl/fitbod-to-hevy-converter/ in the top 3, opens it, and understands within one screen that it solves their problem.

**Architecture:** Keep the single page and the single URL that Google already knows. Make that page crawlable without JavaScript (build-time prerender, `outputMode: "static"`), give it a proper `<head>` (title, description, canonical, Open Graph, JSON-LD), put the search phrases in real, useful copy (H1 + FAQ), and turn the GitHub repo into a second doorway (description, topics, homepage link). Everything else (Search Console, WordPress links, outreach) is outside the repo and listed as user actions.

**Tech Stack:** Angular 22.1 (standalone, zoneless, signals), `@angular/ssr` + `@angular/platform-server` for prerendering only (no Node server: Strato is static Apache), Vitest, GitHub Actions → SFTP.

## Global Constraints

- Canonical URL is `https://sintaxcode.nl/fitbod-to-hevy-converter/` (trailing slash, https, no www). Never change it; it is indexed and linked from GitHub.
- No analytics, no tracking, no external fonts or CDNs. The page says "nothing is uploaded"; keep that literally true (zero network requests after load).
- One page, one URL. No extra routes or pages in this plan.
- Copy stays English, in the voice of the current page (short, concrete, no marketing filler). Open-source project style (user direction 2026-09-08, relayed from the issue-#3 session): describe what the tool does; no "free", no "bring your history with you", no benefit-led slogans in titles, descriptions, Open Graph, JSON-LD, README or the share image.
- Bundle budget unchanged (`initial` ≤ 500 kB warning); component style budget: if `ng build` warns on `anyComponentStyle`, raise `maximumWarning` to `10kB` in `angular.json` (error stays `12kB`).
- All specs keep passing, none skipped (`npx ng test --watch=false`; 65 when the plan was written, the suite has grown since).
- Commits: per `~/.claude/CLAUDE.md` nothing is committed without the user's explicit go in the session. The commit steps below are the intended granularity, not authorization.

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Canonical URL stays `/fitbod-to-hevy-converter/`. Fix `BASE_HREF` to match; do **not** move to `/fitbod-to-hevy/`. | It is indexed, ranks, and every existing link (GitHub, gist comments) points there. A move costs weeks and needs a 301 that Strato's WordPress `.htaccess` would have to own. |
| D2 | Prerender at build time (`outputMode: "static"`), no SSR server. | Strato is plain Apache; static HTML is enough for a one-page app. Same `browser/` output dir, deploy unchanged. |
| D3 | Search phrases go into the H1 and a collapsed FAQ on the same page, not into extra pages. | One URL concentrates the few links this niche has. Split into pages only if Search Console later shows distinct query clusters. |
| D4 | No analytics. Measure with Search Console only. | The page promises nothing is uploaded; a tracker would make that false. |
| D5 | GitHub repo metadata + README are part of the plan. | The repo already outranks the site for one query; it should say what the tool is and link the live page. |

```apache
  RewriteBase ${BASE_HREF}

  # because this file starts its own RewriteEngine, so repeat the redirects.
  # Loop-safe when TLS is terminated in front of Apache: only redirect when no layer says https.

  RewriteCond %{HTTP:X-Forwarded-Proto} !=https

  RewriteRule ^ https://sintaxcode.nl%{REQUEST_URI} [R=301,L]

  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^(.*)$ index.html [L]
</IfModule>
```

- [ ] **Step 4: Guard the one constructor-time browser call**

In `src/app/app.ts`, `detectFileSharing()` — add the first line inside the function, before `try`:

```ts
function detectFileSharing(): boolean {
    if (typeof window === 'undefined') {
        return false;
    }
    try {
        return (
            typeof window.matchMedia === 'function' &&
            window.matchMedia('(pointer: coarse)').matches &&
            typeof navigator.canShare === 'function' &&
            navigator.canShare({ files: [new File([''], 'probe.csv', { type: 'text/csv' })] })
        );
    } catch {
        return false;
    }
}
```
